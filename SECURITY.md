# Security policy

This project handles local configuration that may be adjacent to credentials and private work. A generated portable repository must be treated as sensitive until its complete tree and Git history have passed review.

Do not include real credentials, authentication files, session data, private project content, local identifiers, or secret-shaped test fixtures in issues or pull requests. Use obvious placeholders such as `EXAMPLE_TOKEN` and `example.com`.

Report a suspected vulnerability privately through the repository host's security-advisory feature. Do not post a working secret-exfiltration example in a public issue.
